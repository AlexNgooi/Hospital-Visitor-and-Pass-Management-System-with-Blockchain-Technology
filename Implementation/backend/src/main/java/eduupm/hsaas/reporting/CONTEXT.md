# M06 reporting boundary

- Inputs: planning/03 A03-A04/D, planning/14 C18-C20, actual V5 submitted_at and approved M05 V6 cards/card_assignments.
- Responsibility: real MySQL ADMIN aggregate read model and audited masked registration CSV. No fixture fallback or NOT_IMPLEMENTED response.
- C22 source/environment boundary: every registration count/group/preview/export requires the FoundationProperties environment and data_origin=SYNTHETIC. Assignment metrics additionally require the same configured environment and operation_origin=SIMULATED; inventory requires that environment and data_origin=SIMULATED. Environment comes only from backend release configuration, never query input, and is shown in report origin. No cross-environment aggregate is authorized.
- Date semantics: inclusive MYT calendar inputs become UTC [from midnight,to+1 midnight), up to 366 days. Visits use submitted_at, issues use issued_at, returns use returned_at, lost closures use closed_at+LOST. Category/destination filters join registrations. Open/overdue are current at serverUpdatedAt and ignore selected historical dates; overdue is closed_at IS NULL AND due_at<=asOf, independent of scheduler.
- Inventory: category filter only, explicitly ignores ward because available/unassigned cards have no ward. Utilisation is ISSUED/OVERDUE inventory count divided by all enrolled cards (including lost/disabled), not a historic occupancy percentage.
- Snapshot: all metric groups share one UNION statement at READ_COMMITTED. Preview is a subsequent statement, so activity concurrent with refresh can reach the preview slightly before the metric snapshot; the next five-second poll converges. No historic-as-of reconstruction is claimed.
- Export: select at most 10001; reject more than 10000, never truncate silently. No form_data is selected; visitor label is ***. Quote every CSV field and prefix potentially executable formula cells after leading control/space/format characters. Measure actual JSON-escaped Export UTF-8 bytes against 1047552 before audit inserts, leaving margin below the shared client 1MiB limit. Export record/local audit/history commit before body returns; a lost response may leave an audit without a downloaded file and is never automatically retried.
- Verification: only scoped CSV/MYT tests plus compile/package; live SQL and migration execution pending user/disposable DB. No business service started here.

## R03 manual pass increment (supersedes old M06 source/destination definitions)

- Registration metrics/CSV use V8 registration_destinations with EXISTS; category/day/submission totals count registrations once, never locations or passes. Destination preview labels come from bounded reference names through correlated JSON_ARRAYAGG and deterministic Java sorting; missing relations fail explicitly. Old singleton rows are V8-backfilled.
- Pass metrics/preview/CSV use actual V9 destination_name snapshots. Root destination fallback is ONLY operation_origin=SIMULATED AND assignment.destination_id IS NULL. New manual records never silently fall back. Inactive referenced labels remain readable.
- Deployment is backend-selected. Registrations require data_origin=SYNTHETIC. Assignments additionally require the same environment and exactly SIMULATED/SIMULATED or MANUAL/SYNTHETIC operation_origin/data_origin. Inventory requires SCAN/SIMULATED or MANUAL/SYNTHETIC enrollment_method/data_origin. No PHYSICAL/live broadening.
- Existing visits/issued/returned/lost/inUse metrics retain their denominators. issuedRegistrations and openRegistrations count DISTINCT registration_id in their respective period/current scopes; noDeadline counts current open assignments with due_at IS NULL. overdue explicitly requires nonnull due_at<=captured serverUpdatedAt and closed_at IS NULL.
- Pass preview/export uses issue OR actual RETURNED return OR LOST closure within selected MYT range, once per assignment. Current metrics ignore period dates. Lost is never an actual return; full issued/returned/closed UTC API timestamps and staff IDs are preserved. Unknown legacy closer remains nullable and is labelled unavailable.
- POST /api/admin/reports/pass-exports is ADMIN/session/CSRF protected and has the existing export row/escaped-JSON bounds, audit, history and no-retry behavior. File prefix is hsaas-passes; registration prefix remains hsaas-masked. No form_data/name/IC/MRN/phone/address query or output.
- No V10, migration execution, application startup or test bodies. Only source review and necessary compile/package/build/lint under planning/16; manual SQL/business/concurrency acceptance stays NOT_RUN.
