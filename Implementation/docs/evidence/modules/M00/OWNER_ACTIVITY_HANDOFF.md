## Problem and minimal correction

Previously every successful framework Session save called confirmedSave, so signed-in staff visiting a public anonymous entry endpoint could renew confirmed_idle_expires_at through the automatic request-end save. Omitting an explicit save in the QR service could not fix this boundary. This contradicted planning/02 and planning/04 C12: anonymous exchange/submit must not extend the staff owner lifetime.

Coordinator relayed M02's actual RED: QrMysqlTests#publicEntryDoesNotRenewStaffOwner, disposable MySQL and real same-cookie capabilities GET → exchange POST → entry GET, all 200, owner deadline +600ms. Targeted command exited 1 with 1 failure/0 errors/skips at 2026-10-09 12:44:12 +08. This is M02/coordinator-reported evidence, not a claim that M00 ran its business test.

The outer SessionResponseFilter now establishes a server-only request policy from the decoded Servlet path, excluding contextPath. Exact `/api/public` and the `/api/public/` namespace are excluded, with a segment boundary (not raw URL/header/body classification). GuardedSessionRepository carries the policy across explicit controller saves and the automatic SessionRepositoryFilter tail save, then clears it together with the tracked Session in every finally path. An unscoped save defaults to no owner activation/renewal; no inheritable/client-settable activity flag is introduced.

Every save retains the original sequence: before-save validation and possible committed revoke → release all domain locks → actual isolated JDBC Session save → bounded REQUIRED post-save metadata/mapping/epoch/previous-deadline validation. Only after all checks does a public/non-owner confirmation return without updating the context. Thus a valid public request with staff attributes still succeeds, PENDING remains PENDING, ACTIVE deadline stays fixed, and failed/late/revoked/old-generation authority cannot revive. The framework row can receive normal idle bookkeeping; it cannot substitute for the unchanged conservative owner deadline. Login first activation and normal non-public staff/auth/admin request renewal remain enabled.

Aligned public paths: GET /api/public/csrf; GET /api/public/config/registration; M02 GET /api/public/registration-entry/capabilities, POST /api/public/registration-entry/exchange including restart confirmation, GET /api/public/registration-entry; future POST /api/public/registrations, POST /api/public/mrn-validations and public schema/poll follow the same namespace rule. No new production endpoint was added. The internal confirmedSave hook gained a boolean activity parameter; owner guard/domain ports and wire DTOs are unchanged.

Source changes are limited to GuardedSessionRepository, SessionCapabilities, SessionResponseFilter and the existing integration test class; README/auth/config contexts and SESSION_SPIKE explain the corrected boundary. Accurate English comments cover request policy, save ordering, no-renew placement and test fixture responsibilities. No frontend/planning/M02 production code, dependency, lock order, domain transaction structure or V1–V3 SQL changed. No native database, .env, real admin, push/merge or deployment was used.
